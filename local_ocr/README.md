# 本地 OCR 的耗时与进度

本地 OCR 仍使用相同的 CPU PaddleOCR PP-StructureV3、相同模型权重和 200 DPI 输入；本次没有降低图片分辨率或停用表格识别。

- 默认启用 MKLDNN/oneDNN 优化 CPU 推理。已用同一份三页文档比较：标准 CPU 355.0 秒，优化 CPU 217.3 秒；纯逐页识别部分约 347.7 秒降至 163.3 秒。初始化冷热缓存不同，数字仅代表本机固定运行时，不是服务器速度保证。
- 两种内核得到的 37 个标准化块，文本、边框、顺序、行、片段、内容均逐项完全一致。德语有表首页也实测从 88.7 秒降至 25.3 秒，其 10 个标准化块（含表格 HTML）逐项完全一致。
- `RETAIN_LOCAL_OCR_MKLDNN=0` 可以关闭 CPU 优化。遇到明确 oneDNN/MKLDNN 不支持或原生子进程崩溃时，默认用标准 CPU 内核重试一次；普通配置或模型文件错误不重试。
- 模型加载、逐页开始/完成及真实耗时现在实时写入既有事件文件。单页较慢时每 15 秒发一条耗时心跳，已完成页数不会虚增。局部图像再识别使用独立 region 单位，不占正文页数。
- 子进程输出实时转发并保留有界错误尾，避免等待整本识别结束后才显示所有页进度。

## 可选延迟表格加载

默认保持完整表格模型立即初始化，免得首个表格页多跑一遍识别。

只有确定文档多数不含表格时，才可设置 `RETAIN_LOCAL_OCR_LAZY_TABLES=1`。该模式先读取原始布局检测的 table 信号，若发现表格或缺失布局信息，使用原完整模型重新识别该页，之后复用完整模型。

实际验证：无表三页的可选模式约 177.1 秒，与标准化结果逐项完全一致；有表首页从 25.3 秒增加到 38.6 秒，但其表格 HTML 和标准化结果完全一致。因此没有把此模式设为默认，也不承诺它对所有文档都更快。

上述配置都属于可选部署设置；现有 Dify 表单、接口和实际 .env 没有改动。镜像构建时的模型预热仍用原标准 CPU 语义，运行任务时才默认使用已验证的优化内核及兼容回退。
